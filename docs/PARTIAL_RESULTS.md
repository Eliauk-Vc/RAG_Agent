# 独立预算与中断后的部分结果

默认及本项目 `.env`：`WORKFLOW_LLM_TOKEN_BUDGET=50000`，`WORKFLOW_EMBEDDING_TOKEN_BUDGET=250000`。两种用量独立累计、独立限制，旧的 `WORKFLOW_TOKEN_BUDGET` 不再生效。每次完整工作流重新计量，不累计整个会话；嵌入预算可改成 200000–300000 范围内的值。

LLM 总预算内部为收尾预留 8000 tokens，不额外增加 5 万上限。接口调用前按 UTF-8 字节、消息开销和最大输出估算并预占用量，嵌入并发调用共享预占额度，完成后按服务返回的实际用量继续计算。预算检查位于模型/嵌入适配层和工作流阶段边界。这样会保守地提前停止，显示用量未达到上限也可能因下一次输入估算和预留额度不足而停止；不是精确 tokenizer 计费预测。远端用量仅在返回后可见，服务内部重试/异常未返回用量等不能当作零实际费用。

达到预算、最大轮数或异常中断时，若已有证据：

1. 收集已返回的子任务证据，包括回答生成失败但保留下来的证据，以 RRF 融合。
2. 在剩余 LLM 额度内进行一次基于原文的部分整理，不调用通用知识补齐。
3. 显式列出未启动、未完成的子任务及审核发现的问题；最终审核没完成也会标注。
4. 如果连整理调用也无法执行，直接提供有限长度的原文摘录，注明尚未综合核对。
5. 返回 `partial`，保留证据、会话和任务状态，可导出并继续追问，不计为完整评估成功。

只有没有可用证据且 LLM 仍有额度时才进入有标签的通用知识兜底；额度耗尽不会再越过上限发起兜底调用。用户主动取消仍直接取消，不触发额外整理。

聊天与专题任务监控分别显示 LLM 和嵌入的“已用/上限”，部分结果显示中断原因。修改需重启服务生效，历史回答不会自动重写。

验证记录：`outputs/qa/partial_budget_live.json` 重跑“请整理资料中几类常见障碍的病程要求，并说明哪些有例外或附加条件。”，返回已有证据支持的 `partial`，明确尚未完成最终审核；报告 LLM 31891、嵌入 90826 tokens。此为功能验证，不是答案准确率评测。
