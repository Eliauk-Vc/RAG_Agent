# 子任务确认充分后执行 MMR（2026-09-15）

当前流程：检索与余弦重排序 → 返回候选（按 ID 去重）→ Agent 判断与补查 → 明确选择 answer → 对选定证据执行 MMR，最多保留 6 条 → 生成子任务答案。跨子任务 RRF 不变。

检索阶段不再通过 MMR 缩减候选。候选数量、证据字节预算和提示词预算仍然生效，并非无限保存原文。MMR 不是事实校验，延后执行也不能保证所有必要条件都被保留。

向量缓存作用域延长为一次 Agent.run，保存原始候选文本映射，最终 MMR 复用重排序向量。不同查询需要各自的查询向量；结束或取消后清理缓存。

只有显式 answer 路径运行 MMR；资料不足、预算强制收尾不执行。MMR 超时或异常时保留输入证据，取消向上传递。trace 的 finalize_evidence 记录输入 ID、筛选状态和数量。

默认保护：模型调用 45 秒、工具调用 40 秒、子任务总计 120 秒；最多 7 次决策、5 次工具、3 次搜索。外层工作流另有总超时、最大轮数与独立 Token 预算。

旧 MMR.md 和 OPEN_ABLATION_REPORT 的实验数据来自迁移前流程，不代表本次改动后的效果。新流程目前完成离线回归验证，未重新进行真实模型效果评测。

## 取消固定候选扩展

每次 search_knowledge 按请求的 top_k 返回候选，不再乘以三，且不受 MMR 开关影响。旧 AGENT_MMR_FETCH_MULTIPLIER 配置不再读取。候选总 Token 预算统一为 16000，已有证据与提示词长度限制仍然有效。MMR 仍在子任务确认充分后执行。
