# RRF 前后对照评估

日期：2026-09-13。环境：D:\Anaconda3\envs\lightrag。结论：本轮没有观察到 RRF 提升，不能推断整体系统达到下表准确率。

## 方法

使用现有 7 道病程/症状问题，核对知识库正文中直接回答问题的片段作为相关性标注，排除目录和仅提及疾病名称的段落。这是严格的“直接答案片段”口径，不涵盖全部背景相关性。标注及对应原文保存在 `outputs/evaluation/rrf_ablation/labels.json` 和 `gold_source_records.json`。

真实运行 7 次基础 Agent，每次保留证据和执行轨迹。固定这些结果，分别应用修改前的轮流合并与修改后的 RRF（k=60）。两组均使用当前配置的 18000 字节证据预算。额外组成 4 个复合问题，包含 2、3、2、5 个子问题，分别生成前后两组汇总答案。模型和汇总提示词相同，证据顺序及 RRF 元数据随融合策略变化。

这是隔离融合阶段的对照实验：固定拆分，未运行完整工作流的规划、最终审核与补充检索；不是两个完整版本的端到端评测。7 个控制题与 4 个组合题复用证据，不是 11 个独立样本。生成各执行一次，未估计随机波动。

## 结果

| 指标 | 修改前 | RRF 后 |
|---|---:|---:|
| 7 个单问题直接答案片段召回率（宏平均） | 100% | 100% |
| 7 个单问题检索精确率（宏平均） | 100% | 100% |
| 4 个复合问题直接答案片段召回率（宏平均） | 100% | 100% |
| 4 个复合问题检索精确率（宏平均） | 100% | 100% |
| 汇总答案完整正确率，按子问题计 | 11/12，91.7% | 11/12，91.7% |
| 所有子问题都完整正确的复合问题比例 | 3/4，75% | 3/4，75% |

召回率 = 选中的已标注相关片段数 / 已标注相关片段总数。检索精确率 = 选中的已标注相关片段数 / 所选片段数。两者均在融合后的整个证据集合上计算，不是候选检索池的精确率，也不是医学正确率。

答案由 Codex 助手逐项对照原文审阅，未经独立人工复核。必须同时满足病程数字和必要条件，不能仅凭关键词命中判定正确。12 个子答案中，两组各有一个不完整：第五类组合中的精神分裂症病程，修改前省略情感症状需减轻到不再满足诊断标准的限定，修改后漏掉相应两周条件。详细判定见 `answer_review.json`；两种遗漏严重程度不同，二元分数没有体现这个差异。

## 如何理解

此次每个基础 Agent 最终只保留一个直接答案片段；组合后去重只剩 1–4 个，全部能放进预算。因此 RRF 主要改变顺序，没有增加或排除证据，指标已达到本小样本的检索上限。证据齐全仍可能在生成时丢失条件，RRF 不能解决此类遗漏，也不能自动判断事实真假。

这些结果不足以证明 RRF 在更多文档、噪声、矛盾资料或预算紧张时有效或无效。下一轮应增加独立标注的复杂问题和多文档样本，并分别评测融合、最终审核、完整工作流。没有为了制造提升而人为添加干扰片段或缩小当前预算。

本轮服务报告用量：LLM 68,552 tokens（36 次调用），嵌入 92,532 tokens（21 次调用）。用量覆盖候选生成和两组汇总；未据此估算费用。

## 文件与复现

- `rag_app/evaluate_rrf.py`：执行脚本，运行 `D:\Anaconda3\envs\lightrag\python.exe -m rag_app.evaluate_rrf`。
- `outputs/evaluation/rrf_ablation/results.json`：逐题指标、证据 ID、汇总原文及本次用量。
- `outputs/evaluation/rrf_ablation/subtask_*.json`：冻结的真实 Agent 输出和轨迹。
- `outputs/evaluation/rrf_ablation/answer_review.json`：答案审阅口径和逐题判定。

脚本默认复用该输出目录已有的子任务和答案，便于复算融合指标；这不是重新采样。要做全新实验，先将 OUT 指向一个新的空目录；更换模型、索引或预算后不可沿用旧答案。本报告针对本次已保存的结果，后续重新生成后需重新审阅答案。
